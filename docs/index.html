Overview

What it is

A platform that authorizes and captures payments, records every money movement in an immutable double-entry ledger, keeps strict per-tenant isolation, and lets users ask about their finances in plain English — grounded in real ledger data.

💳Payments

Idempotent authorize/capture with an Idempotency-Key — retries never double-charge.

📒Ledger

Every transaction posts a balanced double-entry that nets to zero — proven by invariant tests.

🏢Multi-tenant

Tenant isolation enforced server-side on every hop, never by client trust.

🤖AI query

“What’s my cash balance?” → a grounded answer via a tenant-scoped tool-use loop.

The hard parts

Problems it solves

The interesting engineering is in the failure modes — consistency, isolation, and resilience under load.

💸 Money must never be lost or double-counted

Double-entry ledger that nets to zero (enforced by property/invariant tests) + idempotent operations, so retries are safe.

🔗 Consistency without a distributed transaction

The transactional outbox ships events reliably; a saga with compensation auto-voids a payment when the ledger rejects it.

🛡️ One tenant must never see another’s data

Server-side tenant scoping on every request and every AI tool call — a jailbroken model still can’t cross tenants.

⚡ Survive load & partial failure

Rate limiting, cache-aside, circuit breakers, retries/backoff, and dead-letter queues for poison messages.

System design

Architecture

Four independently deployable services over a Kafka event backbone. Consumers run as standalone workers, never in the request cycle.

Depth

Engineering highlights

🧩Distributed systems

  • Saga with compensation, transactional outbox, idempotent consumers (event-id dedupe + state-based).
  • At-least-once delivery with commit-after-processing; poison-message DLQ + exponential backoff.
  • Avro schema evolution (BACKWARD); per-key ordering via partition keys.

🛡️API resilience (gateway)

  • Atomic Redis token-bucket rate limiting (Lua).
  • Cache-aside with invalidate-on-write; circuit breaker (closed/open/half-open).
  • Cursor (keyset) pagination; edge JWT auth; one token works on every hop.

🤖AI layer — safety first

  • The model never writes SQL and never picks a tenant — only two safe, tenant-scoped read tools.
  • Tools run through the gateway with the caller’s JWT — isolation enforced in code, not model goodwill.
  • Multi-provider gateway with failover, per-provider breakers, token/cost accounting; a standalone MCP server.

🚀Delivery & operations

  • CI runs real test suites every commit (Django vs ephemeral Postgres; hermetic gateway/AI), then builds all images.
  • One DRY Helm chart renders every service + worker; Terraform installs it.
  • The whole stack — incl. optional in-cluster Kafka — runs on a local Kubernetes cluster.
